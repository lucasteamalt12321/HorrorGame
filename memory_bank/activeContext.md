# Active Context — HorrorGame

## Текущий фокус

- **ИТЕРАЦИЯ 5 — PHASE 19-23: полировка, QA, release.** Код проверен headless-тестами: smoke 241/241 PASS, boot 34/34 PASS. Deliverables — 96%. **Сборка Android выведена из внешнего блокера**: тулчейн установлен, APK 109.9 MB собирается и подписан. **Краш «Новая смена» НЕ исправлен**, экран компьютера на Android НЕ исправлен — оба ждут телефона.

**Жалоба игрока «в спавн-комнате ничего не работает» закрыта.** Три независимые причины, все были релиз-блокерами:
1. Мышь физически не доходила до рабочего стола: Godot не передаёт события из корневого `Viewport` в 3D-встроенный `SubViewport`. Добавлен явный маршрут `GameRoot._input` → `ComputerSystem.get_monitor().route_input()` → ray на экранный quad → `ScreenViewport.push_input()`.
2. Полноэкранный `WindowLayer` в `desktop.tscn` стоял выше иконок с `mouse_filter = PASS`. В Godot `PASS` не «пропускает» событие вниз, а затеняет всё под собой: окна открывались и выглядели нормально, но ни одна кнопка не нажималась. `WindowLayer`, `Taskbar` и подписи → `IGNORE`.
3. Первое ESC во время загрузки глоталось `close_top()`, а у экрана был свой таймер загрузки вразрез с системным. Теперь `ComputerSystem.is_booting()` — единственный источник, первый ESC пропускает анимацию, второй выводит из сессии.

Закрыто в этой итерации:
- **DL-06** — все 4 уровня 2D-игры проверены автоматически: геометрия, спавн в пределах поля, достижимость цели, согласованность таблицы зон, активация бага в зоне с учётом гейт-дизайна, старт/стоп, пикапы.
- **DL-07** — `CameraSystem` (видоискатель на ПКМ, плавный FOV, стабилизация look) + фонарь на F. Галерея фото починена (сцена ссылалась на несуществующий путь родителя) и покрыта тестом.
- **DL-11** — `cursor_followed` реализован через `CursorWatcher` + флаг `saw_pause_anomaly`; канон приведён к проверяемым фактам, добавлен инвариант `TODO ⇒ safe_facts пуст` и `CanonRegistry.validate()`.
- **Настройки** — `fullscreen` и `ui_scale` реально применяются, `touch_controls` подключён, дубль `screen_shake` удалён.
- **Компьютер** — исправлен баг-релиз-блокер: окна всех пяти приложений не создавались (`APP_SCENES` был задан enum-ключами, а роутер передаёт строковые id). Плюс битые `$`-пути в `mail_app.gd` и `files_app.gd`. Теперь smoke открывает каждое приложение.
- **Долги** — `report_opened` подключён, `player_model.obj` удалён, `AudioManager.shutdown()`, рабочий watchdog в `boot.gd`.
- **Release** — создан `export_presets.cfg` (Windows Desktop), `/build/` в `.gitignore`, `docs/` и Memory Bank синхронизированы.
- **Android-пресет** — требование «работать на всех устройствах» закрыто конфигурацией, а не кодом: universal APK (`armeabi-v7a`/`arm64-v8a`/`x86`/`x86_64`), без Gradle-сборки, `GL Compatibility`, `Sensor Landscape`, `immersive` + `edge-to-edge`, все размеры экрана, ETC2/ASTC, иконки из `res://icon.svg`, ноль разрешений, подпись debug-keystore для `adb install`. Ориентация — проектная настройка `display/window/handheld/orientation=4`: в 4.7 в пресете её нет. Пресет проверен `--export-release "Android"`: движок его узнаёт, падение даёт только отсутствие export templates, JDK и SDK `build-tools`. Мобильный ввод не дублировался — работает `emulate_mouse_from_touch` (по умолчанию `true`), touch тянет джойстик, кнопки и 2D-игру в мониторе.
- **Краш Android «Новая смена» локализован, но НЕ исправлен.** Это не «не воспроизводится», а нативный краш: 6 записей `data_app_native_crash` в Dropbox, `SIGSEGV (SEGV_ACCERR)` в `libgodot_android.so` со стеком `AudioTrackCallback::onMoreData` → `processAudioBuffer` → `AudioTrackThread::threadLoop`, то есть порча кучи прямо в аудиопотоке микшера. GPU (Mali-G615) в стеке не участвует — рендер ни при чём. Код на `/sdcard/HorrorGame` совпадал с HEAD по MD5, устаревший клон был ложным следом. Процесс до падения живёт 6.0-6.5 с, то есть падение приходится на синтез looping-стримов в `_start_loops()`. Гипотеза «`MIX_RATE` 22050 + подмена `stream` играющего плеера» **не подтвердилась**: после `bc8e8a3` комната не успевает прорисоваться вовсе. Статус DL-16 — `blocked`, ручного подтверждения игроком не было.
- **Регрессии на ввод** — boot-тест проходит пользовательский путь целиком (E → ожидание загрузки → клик по иконке → ESC), smoke проверяет настоящим motion-событием, что каждая кнопка в каждом окне приложения вообще достижима мышью. Оба теста ловили бы возврат этого бага.

## Следующие шаги (по приоритету)

1. **Когда вернётся телефон — прогнать APK самому, а не глазами игрока.** APK уже собран: `build/android/HorrorGame-debug.apk` (109.9 MB), ставится `adb install -r -g`. План: `am start` → bounded `adb logcat -d` (без бесконечного логката) → `dumpsys dropbox --print data_app_native_crash` для нативных падений → сравнение последовательных `screencap` для проверки live-экрана компьютера. Только так отличить «fixed» от «не воспроизводится». **Пока игрок не прошёл проект целиком, DL-16 и DL-14 не закрывать.**
2. **DL-14 — хоррор-темп и полировка.** Единственный оставшийся deliverable, который нельзя закрыть кодом: ручное прохождение в окне по главам 1-10, проверка читаемости UI, звука и темпа 2D/3D. Первым делом стоит кликнуть иконки и поработать в окнах — теперь это должно работать, но вживую ещё не проверено.
3. **DL-15 — сборка `.exe`.** Блокер снят: 03.10.2026 собраны `.exe` (104 MB) и `.pck` (470 992 Б). Осталась только ручная проверка запуска в окне на Windows.
4. **DL-16 — APK собран, остался прогон на устройстве.** Пресет валиден, тулчейн установлен, `--export-debug` даёт подписанный APK. Дальше — `adb install -r` и прогон «Новая смена». Сборка только на ПК: `git pull` на телефоне синхронизирует код, но Godot 4.7 Android Editor экспериментальный.
5. **Edge cases, которые тест ещё не закрывает:** сохранение в середине главы, повторный вход в 2D-игру, двойное нажатие E, отсутствие прогресса в БД после загрузки старого сейва (проверить `migrate()`).
6. **Ручной QA на мобильном устройстве** — touch отправляет те же actions и эмулирует мышь, но safe-area и тач-таргеты вживую не проверены; журнал нативных крашей снимать через Dropbox, а `logcat` только bounded-порциями.
7. **Отдельно: неотслеживаемый `addons/copy_all_errors/` попадает в сборку.** Он упаковывается и в `.exe`, и в `.apk`, хотя не добавлен в git и не является частью игры. Решить: исключить из экспорта или удалить.
8. **Warning о `AudioStreamPlaybackWAV` при выходе из headless** доказано нелечимым из проекта (держит `AudioServer`); если понадобится чистый вывод CI — фильтровать в скрипте прогона.

- **Канон:** внешнего источника нет. `LTL`, `eight-nine`, `Nine Circles`, `Чайная религия` существуют только как неоднозначные игровые строки. Не выдумывать факты; любой новый факт проходит через `safe_facts` + `CanonRegistry.validate()`.
- `player_model.obj` удалён в ИТЕРАЦИИ 5 — пункт снят.
- Что считать релизным артефактом без templates: `.pck` или документация сборки для CI.

## Правила для следующих сессий

- После любых новых `class_name` — `--headless --editor --quit`, затем **оба** теста: `smoke.tscn` и `boot.tscn`.
- Проценты считаются только по `projectbrief.md` → `## Project Deliverables`.
- Сцена не должна ссылаться на несуществующий путь родителя — ловится `--export-pack` и smoke-проверкой узлов.
- Полноэкранные `Control` в 2D-интерфейсах — только с `mouse_filter = IGNORE`; иначе они затеняют кнопки под собой, и это не видно ни на скриншоте, ни в тесте на `ui_accept`.
- Тест, повторяющий архитектуру вместо прохода по ней, пропускает релизные баги: клики проверяются настоящими событиями ввода.
- Перед завершением сессии обновить `progress.md` (Changelog + `last_checked_commit`) и `activeContext.md`.
